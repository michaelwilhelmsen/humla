# The session timeline is canonical for a note's content; `note.transcript` is a projection

Humla has kept two copies of a recording's words since sessions landed. `note.transcript` is one string on the note row — what the summary, chat retrieval, embeddings and the edit textarea all read. Each session's `timeline.jsonl` is a list of `{start_ms, end_ms, label, text, words}` entries — what the styled reader renders and what playback highlights against. Both are written by the same post-stop pass, from the same chunks, and nothing keeps them in agreement afterwards.

They already disagree in production. #169 is one note where the transcript opens with a turn the timeline has no entry for, so the reader — which renders `groupTimeline(timeline)` whenever the timeline is non-empty — silently shows a call starting partway in, while the textarea shows it whole. The mechanism is that `combine_with_snapshot` prepends the prior take's transcript to the new one, while `serialize_timeline` writes this session's chunks alone; any snapshot no earlier timeline accounts for is text that lives in the string and nowhere else. Free-text editing is the same shape from the other direction: an edit goes straight to the `transcript` column and no code path writes it back into a timeline, so on any note that has one, the edit is invisible in the view people actually read — permanently, across reopens.

We decided the **timeline is canonical for a note's content, and `note.transcript` is a derived projection of it**. This is a widening of what the timeline already owned: it has been canonical for *labels* since the per-chunk edit commands landed — `note_timeline_set_chunk_label` and `note_timeline_delete_chunk` both mutate the timeline and then rebuild the string. That family is now the only way words enter a note after a recording, and free-text editing joins it (#170) rather than remaining the one path that writes the derived copy directly.

The invariant, stated once: **every line of `note.transcript` is reachable from the merged timelines.** It is pinned by an executable test rather than by this document (`orphaned_snapshot_text_survives_in_the_timeline`), which fails today and must pass when #169 is fixed.

## Considered Options

- **Reconcile the two copies at render time.** The first direction taken on #169: keep both, and align the timeline against the string when they diverge — plain text for uncovered regions, or a visible gap marker. Rejected. It leaves the drift in place and adds a third representation of the grouping rule to maintain; the two existing ones already differ deliberately (Rust groups on label, `groupTimeline` on label *and* session), so alignment code has to normalize across a difference that is correct on both sides. It also does nothing about edits, which are the more frequent cause.
- **Make `draft.transcript` authoritative and treat the timeline as a pure highlighting overlay.** Considered seriously, and the reporter and maintainer both initially favoured it. Rejected because it inverts the dependency without removing it: word timings, speaker identity and session boundaries all live in the timeline, so an authoritative string has to be re-attached to them on every edit — which is the alignment problem again, relocated to write time, on data that has no stable key to align by once the text changes.
- **Keep both copies and add an invariant check that degrades the reader.** Retained as a *guard*, not as the decision — a note whose transcript exceeds its projection falls back to the plain reader so the text stays visible. Useful for shapes we cannot prevent (a timeline present but short because `parse_session_timeline` skipped malformed lines; a best-effort per-asset sync download that dropped a file). Insufficient as the answer, because it makes the failure honest rather than absent.
- **One canonical source: the timeline (chosen).** The drift cannot happen by construction, and no reconciliation code exists to keep correct.

## Consequences

- **A recording that lands text must write a session.** The paths that currently don't are the bug's origin: `diarize_and_apply` returns early when the diarize model isn't downloaded, *before* both `set_transcript` and `write_playback_assets`, so the recording ends with live-appended text, no session and no timeline; a crash or interrupted stop after the live append does the same; `write_playback_assets` is explicitly best-effort. Under this ADR each of those still writes a session, serialized from the chunks with empty labels and no words. Text without a timeline entry behind it is now a defect, not a tolerated state.
- **Existing notes need repair, not just prevention.** Four operations rebuild the transcript from the timelines — cycling a chunk's speaker label, deleting a chunk, re-diarizing, unifying sessions — and on a note with orphaned text any of them deletes it outright, taking it out of the summary, chat retrieval and embeddings. Repair therefore has to reach notes recorded before the write-time rule. It runs **on note open**, synthesizing a label-less session for orphaned text: the merged timeline is already parsed and in memory at that point, so detection is a comparison over existing data rather than new I/O, and every destructive path is a UI action on an open note, so the repair always precedes them. A startup sweep over the whole library was rejected as paying for 100+ notes on every launch to fix a handful.
- **The reader can render a note with no labels and no word timings.** A synthesized session has both empty. Turn-level highlighting still works — it is computed from entry bounds, not from words — so only per-word karaoke is lost, on the affected turns.
- **This narrows ADR-0002 without contradicting it.** Speaker identity is still derived and still asserted in exactly one place, but that place is now the timeline entry's `label`, and `notes.speakers` derives from a string that is itself derived. 0002's mechanical test — *if it cannot be rebuilt from transcripts plus the roster, it is a record rather than a cache* — is unaffected: the timeline is a transcript, in a shape that keeps timing.
- **`note.transcript` stays the read surface for everything downstream.** Summary, chat retrieval, embeddings, search and export continue to read the column. Nothing about this decision asks them to understand sessions; it only changes who is allowed to write it.
- **Known cost: an edit loses that turn's word timings.** Rewriting a turn's text invalidates its word-level mapping, and the entry's `words` is cleared rather than guessed at. A stale mapping is worse than none, and turn-level highlighting survives.
- **Notes with no timeline at all keep free-text editing.** With no second copy there is nothing to orphan, so the textarea path is safe there by definition and stays as it is. This is the pre-sessions/legacy shape, not a transitional state to remove.
