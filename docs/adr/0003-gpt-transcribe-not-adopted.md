# `gpt-transcribe` is not adopted — not as the default, and not as an option

OpenAI's `gpt-transcribe` (released 2026-07-28) looked like a straight upgrade to `whisper-1`, Humla's fresh-install STT default: ~25% cheaper and materially better at multilingual speech, which is precisely Humla's Norwegian/English meeting case. #125 filed it as "add it, and make it the default if we can preserve current functionality", and #127 charted a map to produce a decision-complete PRD. Four research tickets ran against the live API and real production audio. We decided **not to adopt the model at all** — the map is closed without reaching its destination, and #125 is closed `wontfix`.

The decision does not rest on the model being bad. It rests on **every claimed advantage being smaller than it looked, and the one real cost being unavoidable**:

- **Word timestamps are impossible, not merely unconfirmed** (#128). `response_format=verbose_json` is rejected outright for this model — `json` and `text` are the only formats — so `timestamp_granularities[]=word` is unreachable at any setting. Word timestamps drive the note's word-by-word playback highlight, and `whisper-1` is the only OpenAI model that returns them. #125's own acceptance rule ("default flipped **only** if word timestamps survive") therefore fails on fact.
- **The quality gain is marginal and hard to see** (#129). Six chunks cut at real production VAD boundaries from a real mixed Norwegian/English recording, each arm fed the `prior_context` and custom vocabulary a production run would have had. Human verdict, recorded in these words: *marginally more accurate, but the margin is hard to see*. Wins and losses both present — `"de urellene"` → `"de URL-ene"` gained, one chunk read better under `whisper-1`.
- **The price cut is not verified from primary source** (#128). Both OpenAI pricing URLs return 403; $0.0045/min vs $0.006/min rests on six agreeing aggregators — the same class of source whose WER figures this effort already had to retract. On a personal-scale per-user audio volume, 25% of a fraction of a cent per minute is not a decision driver even if true.
- **The one genuine advantage is already covered.** `gpt-transcribe` did not hallucinate on silence in any arm, where `whisper-1` fabricated a subtitle credit *and* echoed its prompt verbatim (#133). That is a real win in exactly Humla's worst failure mode — but Humla already spends an RMS silence gate, `is_likely_hallucination` and repetition-collapse guards on it, and those guards stay regardless of provider.

**Adding it as a non-default option was rejected too, because the option is not free.** `languages` (plural, repeated field) replaces the singular `language`, which is a **silent no-op** on this model — so the branch has to live inside `openai_compat::transcribe`, a code path shared with Groq and self-hosted Whisper servers that still need the singular form. Worse, `languages` validates against an allowlist: of the 100 non-`auto` codes in `src/lib/languages.ts`, **37 are rejected with a 400** — a *failed* transcription rather than a degraded one — and `nn` (Nynorsk) is among them, in a Norwegian-first app. That list is version-pinned to one probe and can change under us without notice. Custom vocabulary would also have to move from the merged prompt string into `keywords` for this model alone (#133). That is a permanent per-model special case in the shared transcriber, plus a language-support cliff, bought with a gain a human could barely see.

## Considered Options

- **Flip the default to `gpt-transcribe`.** Rejected: a marginal, hard-to-see accuracy gain and an unverified price cut do not pay for silently disabling playback highlight on every fresh install that never chose it.
- **Ship it as a selectable option, `whisper-1` stays default.** Rejected — this was #125's own fallback and the likeliest outcome for most of the map's life. It fails on the *cost of the option*, not on the model: the `languages` branch, the 63/37 allowlist, and the `keywords` split are permanent complexity in a shared code path, and the picker would additionally need capability copy to stop the karaoke trap being silent. Nobody would have a reason to switch to it.
- **Wait and revisit when OpenAI adds word timestamps.** Effectively chosen — see the reopening conditions below. Recorded as a deferral, not as work.
- **Adopt nothing; `whisper-1` remains the OpenAI default (chosen).**

## Consequences

- **`whisper-1` remains the fresh-install default**, and `TRANSCRIBE_MODELS`, `openai_compat::transcribe`, `supports_word_timestamps`, `skip_prompt_for_model` and `TranscribeConfig::default_fallback` are all unchanged. No migration, no user-visible change.
- **`skip_prompt_for_model` stays a single `Option<&str>`**, still serving `gpt-4o-transcribe-diarize` alone (#133). The "make it a list" refactor #125 anticipated has no trigger.
- **The research stands on disk and is the reason not to redo it**: `docs/research/gpt-transcribe-param-surface.md` (live parameter surface, the allowlist, the timestamp rejection), `docs/research/gpt-transcribe-bias-payload.md` (the `prompt`/`keywords` differential), `docs/research/openai-stt-2026-07.md` and `docs/research/openai-stt-launch-video.md` (with the WER retraction at the top). Anyone reopening this should read them before spending a call.
- **Two methodology facts outlive the decision.** `/v1/audio/transcriptions` returns **HTTP 200 for an entirely invented parameter** — it silently ignores unknown multipart fields, so no future probe of this endpoint may conclude anything from a status code; establish behaviour by differential test or explicit rejection. And **`prompt` on this model family is lexical priming, not topical context**: supplying a meeting's actual words biases decoding, describing its topic buys nothing. That is why Humla's trailing-150-words `prior_context` is the right shape and a summarised prompt would have been the wrong one.
- **The mid-utterance ellipsis is a pre-existing Humla issue, not a `gpt-transcribe` artefact** (#134, corrected by #129's setup). Across the same six chunks, `gpt-transcribe` emitted `…` in 1–2 of 6 while **`whisper-1` emitted ASCII `...` in 5 of 6**. Closing this decision does not close that: whether the post-processing guards handle a trailing elision, and whether the two representations should be normalised, is a live question about the *current* default and belongs on its own ticket if it ever bites.
- **The silent-karaoke trap survives, knowingly.** `gpt-4o-transcribe` is already selectable today and already returns no word timestamps, so choosing it silently stops the playback highlight with nothing in the picker saying so. This decision declines to fix that as part of a model it isn't shipping; the gap is pre-existing and unchanged.
- **What would reopen this:** OpenAI shipping word timestamps (or any `verbose_json` equivalent) for the model; evidence that the silence-hallucination advantage is load-bearing, i.e. Humla's own guards measurably failing on real recordings; or per-minute cost becoming material at a scale Humla doesn't have today (a workspace paying for many users' audio, with the price confirmed from primary source). A *new* OpenAI STT generation is a fresh question, not a reopening of this one.
- **This does not weaken the multi-provider design.** `stt::BatchSttAdapter` and `per_language` routing are what made evaluating a fifth model cheap enough to reject on evidence rather than adopt on a launch post. The map cost four research tickets and no production code.
