# Notes, titles and the transcript reader

## The timeline is canonical (#169, [ADR-0004](../adr/0004-the-timeline-is-canonical-for-a-notes-content.md))

The styled reader renders from the merged timelines, so transcript text no timeline accounts for is invisible there, and the first `rebuild_note_transcript` (cycling a label, deleting a chunk, re-diarizing, unifying) deletes it from the transcript, summary input, chat retrieval and embeddings. Three defences:

- **Prevention.** `diarize_and_apply` doesn't return early when the diarize model is missing; it serializes the chunks with an empty label (word timings kept), so the take still writes a session that a later re-diarize can attach to.
- **Repair on open.** `note_timeline_repair` compares `comparable_words` of the transcript with the timelines' projection; `orphaned_prefix` recovers leading lines the projection misses and `synthesize_orphan_timeline` writes them as a session at **manifest index 0**, named "Earlier transcript" (never "Recording 0"). Idempotent; it runs after the workspace session pull. A note with no timeline at all is left alone (it keeps the free-text editor).
- **Render-time guard.** When `coversTranscript` is false, the note falls back to `TranscriptView` over the whole string. The comparison is the backend's; the client never re-derives the grouping rule (Rust groups on label alone, `groupTimeline` on label *and* session). Compare word sequences, never line counts.

`split_label` (Rust) and `parseTranscriptLines` (`Note.tsx`) are the same "`Label: ` prefix" rule; change both. `commit_rebuilt_transcript` refuses to commit an empty projection over a non-empty transcript.

## Editing goes through the timeline (#170)

- On a note with a timeline, editing is per turn: a hover pencil opens the turn, and commit calls `note_timeline_set_chunk_text` with the turn's chunk indices (`TimelineGroup.indices`). It writes the text into the lowest index, empties the rest and re-derives the transcript, like `note_timeline_set_chunk_label` and `note_timeline_delete_chunk`.
- An edited turn drops its word timings and keeps its bounds (it still highlights during playback).
- A note with no timeline keeps the whole-transcript textarea (`TranscriptEditor`).
- Both are locked while a recording is in flight.

## Transcript view

- In the right panel's Transcript tab, styled by default with `white-space: pre-wrap`.
- **A turn is titled with its speaker** (#176): a coloured dot, the name and (in the timeline reader) its time in its own take, with the text full width beneath. Titled at the start of a run of consecutive turns by one speaker. The name is the identity; colour (four, cycling) is the scanning aid.
- Both readers do this — `TranscriptPlayer` (timeline) and `TranscriptView` (fallback, mostly a teammate's note) — through one component, `TurnTitle`. Run rules differ by one thing: `groupTimeline` splits on label and session, the fallback on label alone.
- An unlabelled turn gets no title; in the player it keeps the inline row (the pencil and delete live on the title line).
- `SpeakerLabels`: one quiet name per speaker, derived from the transcript on every render. A click renames it in place, with the note's other speakers listed under the input as merges (a merge is a rename onto an existing label, on this note only). Rename is a line-anchored regex rewrite (`/^Speaker N: /gm` → `/^Michael: /gm`), no metadata table.

## The Transcript tab

- **One row** over a note with text: Clean | Verbatim (when Clean is offered), then `TranscriptSettings` ("Norwegian · 3 speakers") and Copy. `TranscriptSettings` holds what the next transcription uses (language, speaker count) and the runs over this transcript: Detect speakers again (re-diarize, or unify on a note with several takes), Transcribe again, and in Clean, Clean again. Before there is text, the language and speaker pickers stand in the row on their own.
- **A status line**, only when there is something to say: a take not transcribed yet (with Transcribe), where Clean stands (cleaning, partly cleaned, stale, with Clean now), a re-diarize error.
- **The player belongs to Verbatim** (`PlayerBar`, docked under the reader): position, play, 15 s back and forward, speed, volume (`PlaybackVolume`) and, on a note with several takes, which recording plays. Without audio the choice of recording stays, to move between them. Clean has no player and no timestamps; a clean pass's progress shows in both views. The `<audio>` element stays mounted in both, since the reader binds its playback listeners to it once.

## Clean view (#217)

- **A clean transcript beside the verbatim one.** The Transcript tab's Clean | Verbatim switch (`transcript_view`, default Clean; shown while `clean_transcripts` is on and the note has paragraphs to show or a summary provider set up to clean with, `note_clean_available`) shows the note's clean transcript: a model's clean-verbatim rewrite, fillers, stutters and abandoned false starts gone, grammar the speech broke mended, numbers written as numbers, which the user then edits. The timeline and `notes.transcript` stay verbatim and canonical; chat, MCP and webhooks read verbatim. The summary reads the clean transcript, with verbatim where no paragraph covers the words, when the timelines account for the stored transcript (`clean::clean_text`); Copy in Clean copies it, and Export offers it beside Verbatim, defaulting to the view the reader is on.
- **Rewritten per segment.** `commands/clean.rs` cuts each take into segments (one speaker's consecutive entries, about 110 words, cut after a sentence end where one is near) and sends segments per call, as JSON, to the note's summary provider through `resolve_provider` (a governed note is refused like its summary), on the model picked in Settings → Transcription → Clean transcripts (`clean_model`, `<provider>:<model>`, so a pick applies only while that provider summarises), else OpenAI's `CLEAN_OPENAI_MODEL` with `reasoning_effort: "low"`, Copilot's cheapest model, or the user's summary model elsewhere (`clean::light_provider`). A picked OpenAI reasoning model gets `"low"` too; another model gets none. A call holds about 1,000 words on a cloud provider and 240 on a local or custom one (`window_words`), since a small model summarises a long window; three calls are in flight at once. The prompt carries one English before-and-after example and the note's vocabulary (the organisation's and `custom_vocabulary`, `clean_prompt`), so a misheard name comes back spelled as it should be.
- **Guards keep a segment verbatim** when the rewrite drops a negation (`NEGATIONS`; "ikke sant?" is a tag, not one) or drops or changes a number (compared whole, however its digits are grouped), keeps under 35% of a segment of eight words or more, has under 60% of its words aligned to what was said (LCS on folded words; four words or more: a paraphrase or translation), or empties a segment of more than four words. Words are counted as spoken (pause marks and dashes aside), and a word the recogniser ran together or split that the rewrite parted or joined counts as said. An unusable answer leaves its window verbatim.
- **Stored in `notes.clean_transcript`** as a `clean::CleanDoc` (JSON, `v` 1): per take, its paragraphs, each with a stable `id`, the `clean::fingerprint`s (FNV-1a over an entry's words) of the entries it was written from (`members`), where they start (`start_ms`), its speaker and text, and whether the user rewrote it (`edited`) or chose its speaker (`speaker_set`). It syncs with the note (`db::set_clean_transcript`); the user's edits move `updated_at`, a pass's writes don't, so cleaning a note never moves it up the note list: humla-cloud's `notes.clean_transcript`, a text field, decided last-write-wins like the note's other text; a pull from a server without the field keeps the local one. A document of another version is neither shown nor written.
- **The view** (`note_clean_view`, `clean::build_view`): each take's paragraphs placed on its entries by fingerprint where they start (`match_turns`), and the entries no paragraph covers as verbatim gaps, dimmed, or drawn as placeholder lines while a pass runs. A paragraph shows its entries' current speaker unless the user chose one, so a renamed or reassigned speaker follows. A paragraph whose entries changed (a verbatim edit, a re-diarize, the speaker check) no longer matches and is cleaned again, unless the user touched it: then the whole take shows its paragraphs as they are (`stale`), the status line says the transcript changed after the edit, and only "Clean again" writes it anew.
- **Editing** (`note_clean_edit`): a click on a paragraph (or Enter on one with focus) opens it in a card; Enter, Save or leaving the card saves, Escape or Cancel discards; an empty paragraph is refused. The card's speaker chip gives the paragraph another of the note's speakers, applied with the text on Save, so Cancel undoes both. A click that ends a text selection leaves it for copying. Renaming a speaker renames it in the paragraphs too (`clean::rename_speaker`, from `note_timeline_rename`).
- **When it runs** (`clean::CleanRequest`): `Auto` at the end of the post-stop chain, of a deferred transcription and of a re-diarize (it waits for the note to stop being busy), and from the reader when Clean is shown with words no paragraph covers (once per note and coverage per app session). Never `Auto` for a Copilot note, which counts requests: there it waits for "Clean now" (`Missing`). The post-stop pass waits for a pass the reader started rather than skipping its speaker check. "Clean again" (`All`) checks the speaker changes anew ([diarization](diarization-and-echo.md#from-segments-to-turns)) and rewrites every paragraph, edited ones included, after asking when there are any. Failure on the automatic path is silent; the status line names the reason. "Clean again" sits in `TranscriptSettings`. Progress on `clean_status`, in model calls, shown as a percentage. The pass ends with `purge_note_assets_if_gone`.
- **Written per call**, so the reader fills in while the rest is cleaned. Each write reads the stored document again under the database lock and keeps the paragraphs that still match, edits made meanwhile included, adding a fresh one only where none does (`merge_take`); a take an edit made stale meanwhile is left alone. "Clean again" writes once per take, so the old paragraphs stay until the new ones are whole. The pass pings the sync once, at its end.

## Automatic titles (#90)

- A note whose title Humla owns gets a short phrase from its content. `menubar::is_replaceable_title` is the single answer to "may this title be replaced?": empty, a `Recording 19 Aug 14:32` timestamp, or `Imported audio`. A real filename stem is never touched. Mirrored in TS as `isReplaceableTitle` (`src/lib/noteSync.ts`); change both.
- Every trigger reads the note through `title_input`: head of the typed notes, the transcript via `sample_transcript` (whole up to 3,000 chars, otherwise six windows from the middle of six equal stretches), and the summary when one exists.
- Two triggers: the post-stop chain, spawned **concurrently with the diarize pass** (the transcript is final once `recording_stop` drains), and a debounced body-settled checkpoint for a typed note that was never recorded. It runs after `record_detected_language`. Not on summary completion and not during a recording.
- Reuses `resolve_provider`, then the provider's light model (`summary::use_light_model`: OpenAI's `LIGHT_OPENAI_MODEL` without reasoning, Copilot's cheapest, `think: false`).
- Failure is silent on the automatic path and loud on ⋯ → **Regenerate title**, which bypasses eligibility. That item is disabled while the note has nothing to read, while a capture or deferred transcription is changing the transcript, and while a title is being written.
- One-shot: once written, a title is no longer replaceable.
- The call is bracketed by a per-note `title_status` event; the open note shows a shimmer in place of the title.

## Note grid and folders

- All notes and Folder render `NoteCard` in `.nd-notegrid`, with no date headings; the card carries its date (`formatNoteDate`). Card: date, title, four-line excerpt, then state · client · folder.
- **Excerpt** (`noteExcerpt`) prefers the summary's opening line, then typed body, then the transcript with speaker labels stripped. Horizontal rules, model preamble ("Her er …", lines ending in `:`) and fragments under 20 chars are skipped (the first kept only when nothing stronger exists); a fragment body yields to the transcript.
- **Filters on four axes**: status, Client, who recorded it, and a **No folder** toggle. A Folder view renders the same bar with that toggle off (`showUnfiled`). A folder's filter is cleared when the folder changes.
- **The status filter asks what a note has, so its rungs overlap** (`hasStatus`); the card's dot is an exclusive ladder (`noteState`). Separate label maps: `NOTE_STATE_LABEL` / `NOTE_FILTER_LABEL`. Don't read the filter off the ladder: Recorded would then match nothing on default settings.
- `recorded` comes from `notes_with_recordings` (a manifest entry via `resolve_sessions`, not the audio), kept in `useNotesStore.recordedNoteIds` and refreshed when a capture reaches idle and when a replay finishes.
- The owner filter renders only in a workspace with more than one member; "Me" includes notes whose `owner` is empty.
- Multi-select (#19): Cmd/Shift-click, Space, Esc and a checkbox in the card's top-right corner.
- `.nd-well` darkens the scroll region, because the card's edge is only tone (graphite's canvas and surface are both `#ffffff`). Selection is the accent ring, not a fill (`--color-accent-soft` can land darker than the well). Radius from `--radius-card`, shadow from `--shadow-card`. Under `prefers-contrast: more` the card takes a border and drops the shadow.
- `.nd-notegrid`'s track is `minmax(min(var(--card-min, 300px), 100%), 1fr)`; the `min()` stops it overflowing when the column is narrower than one card.
- Folders: a flat list with per-note assignment; sidebar search matches titles, bodies and transcripts and shows each hit's folder.
